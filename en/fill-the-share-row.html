Sourced note

Fill the share row before a cloud agent publishes a live app

Cloud coding agents no longer stop at localhost. Cursor's Build Live Apps flow can scaffold an app, spin up a database, put sign-in behind Cursor SSO, run security checks and hand back a live link, on paid plans with cloud agents enabled.

That moves one decision earlier than most teams expect: who can see what the agent publishes. The share settings are now the blast radius.

The share row

One row, three boxes. Fill it before the first agent publish, while it is a calm task.

BoxThe questionWhat Cursor offers
Who can open the appWho sees it once it is live, and what else can call it?Specific people, groups or your whole team, all behind Cursor sign-in. Public sharing is available on individual plans; on Teams and Enterprise it is off by default unless a team admin turns it on. A Cursor API key lets a script or bot use the app.
Who can approve a blocked publishWhen the security review blocks a publish, who may override it?Team admins can approve a publish the review blocked, except for malicious code, hardcoded secrets or exposed credentials. Otherwise the agent fixes what the check flagged.
How you unpublishIf the wrong thing goes live, who takes it down?Team admins can unpublish any app.

The security checks look for common issues, such as secrets written in app files or exposed credentials. They do not decide who should see the app. That is the row's job.

A filled row (my suggestion, not Cursor's defaults)

BoxSuggested default
Who can openYour team, behind Cursor sign-in
Public shareOff, unless someone writes down a reason for that app
API keysNone, until someone names the script or bot that needs one
Approve blocked publishesOne named team admin, who writes down why they approved it
UnpublishA named team admin, tested once before the first real app

This is not a reason to block live apps. It is a reason to write the row before the first link goes out, instead of during a fire drill after one does.

Test the unpublish path once

Unpublish is the easiest box to leave as a guess, because nobody needs it until something is wrong. On a throwaway app:

  1. Publish it and share it with one teammate.
  2. Have the admin you named unpublish it.
  3. Ask the teammate to open the link again, and note how long it took from "take it down" to gone.
